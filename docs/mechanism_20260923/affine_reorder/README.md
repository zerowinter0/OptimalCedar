# affine 重排成本估计：诊断与最小改进（2026-09-24）

本目录是"affine 在真实重排计划上为什么失准、能否用有依据的建模/剖析修好"这一轮的
小体积交付物。原始捕获与中间 JSON 在 `outputs/affine_reorder_diagnosis_20260924/`，
大体积 payload pickle 在 `tmp_analysis/capture_{declared,pico,cedar,old-dp,v1,v2}/`。

## 1. 实验问题

1. 受控尺寸扫描里 `kx+b` 拟合得很好，为什么迁移到真实重排计划后 Blur 严重低估、
   Jitter 退化、affine 并不总优于比例规则？
2. 误差来自输入统计传播、参数剖析，还是 `kx+b` 的表征能力？
3. 若有改进，其参数能否在不使用目标计划执行时间的前提下获得，并能跨尺寸、跨记录、
   跨合法顺序迁移？

## 2. 结论

1. **主因是"序列化字节"不是工作量的充分统计量，而不是 affine 形式本身。**
   一次合法重排会把 `to_float` 从流水线开头挪到结尾，于是下游算子的输入从
   float32 张量变成 uint8 张量；字节数随之除以 4，但空间尺寸、通道数、真实计算量不变。
   受控证据（同一记录内容、交错多轮、逐调用 p10，见 `blur_geometry.json`）：

   | payload | 元素数 | 字节数 | p10 (ms) |
   | --- | ---: | ---: | ---: |
   | u8 1ch 122×122 | 14,884 | 15,292 | 0.894 |
   | f32 1ch 122×122 | 14,884 | 59,945 | 0.850 |
   | u8 1ch 244×244（真实 PICO/cedar payload） | 59,536 | 59,944 | 2.606 |
   | f32 1ch 244×244（真实 declared payload） | 59,536 | 238,562 | 2.472 |
   | u8 1ch 375×500 | 187,500 | 187,924 | 7.600 |
   | f32 3ch 122×122 | 44,652 | 179,026 | 1.423 |

   字节数相同（≈59.9 kB）的两个 payload 相差 **3.1×**（2.606 vs 0.850）；
   元素数相同、dtype 不同的两个 payload 几乎相同（0.894 vs 0.850、2.606 vs 2.472）。
2. **成本对"元素数（C×H×W）+ 表示类"是良态的**：4 个表示类 × 3 个空间尺度上，
   用两端点拟合、留出中间点，误差多数 < 8%（`operator_matrix.json`）。
3. **误差主要来自成本响应函数，而不是输入统计传播**：六个计划的字节体积传播值与
   实测值一致（`plan_scoring.json` 的 `*p` 列 vs `input_metadata.csv`），
   但字节模型对同一算子的跨计划预测偏 −68% ~ +319%。
4. **最小改进有效**：保留 `kx+b`，只把自变量从"序列化字节"换成"元素数"，
   并给每个 (算子, 表示类) 一对系数（M4）。对**可复现的**流水线内服务时间
   （逐调用 p10 之和），六个计划的预测倍率为 0.98–1.42×；
   而 Cedar 比例规则（M1）与当前字节 affine（M2）为 0.49–11.1×。
5. **仍有一个未解释的上下文项**：每个计划的流水线内逐调用分布都是重尾
   （例如 Blur 的 p10/中位/均值 = 2.56 / 3.49 / 10.6 ms），六个计划都存在，
   与 payload 无关，本轮没有归因。因此绝对吞吐预测仍不能只靠 payload 模型。

## 4. 模型定义（本轮冻结）

| 模型 | 自变量 | 系数 | 来源 |
| --- | --- | --- | --- |
| M1 比例规则 | 序列化字节 | 无（过原点） | Cedar 原生迁移 `t_declared × x / x_declared` |
| M2 字节 affine | 序列化字节 | 每算子一对 | 现网 `physical_model.operator_affine` 的 k、b |
| M3 元素 affine | 元素数 C×H×W | 每算子一对 | 由声明计划自身的 payload 生成 |
| M4 表示感知 affine | 元素数 C×H×W | 每 (算子, 表示类) 一对 | 同上；表示类 = {uint8,float32}×{1ch,3ch} |

拟合协议与现网 profiler 一致：取最小/最大两个层（这里用 122 与 488 两个空间尺度）、
线性拟合 k 与 b；**中间尺度（244）永不参与拟合**，仅作留出点。

## 6. 支持与不支持的结论

支持：

- 重排会改变下游算子的输入表示（dtype、通道数），这是字节特征的盲区；
- 成本在每个表示类内对元素数近似仿射，该形式能跨空间尺度、跨记录、跨合法顺序迁移；
- 用元素数 + 表示类替换字节特征后，六个计划的算子计算量预测显著改善。

不支持（本轮未证明）：

- 未证明改动后 DP 会选择更好的**吞吐**计划：本轮只评估成本估计，未重跑吞吐 campaign；
- 未证明该改动能端到端落地到优化器（DP 需额外传播元素数与表示类，本轮给出成本空间
  证据与设计，实现与回归验证是下一步）；
- 未解释流水线内逐调用分布的重尾，绝对时间预测仍不可靠；
- 未在第二个负载上验证。
