## 新Cost Model设计
1. 使用Boundary表示不同计算后端之间算子传输数据开销。（该设计已被证明十分有效）
2. 使用y=kx+b拟合不同算子在输入单条数据大小变化时其开销变化。而非原cedar的y=x
2. 使用Workers遍历W取值，取最优者。
3. 使用width遍历不同算子不同宽度取值，取最优者。该设计一般需要基于Workers设计。
4. 使用max(Ray-Sum-Cost+Ray-Boundary, SMP-Sum-Cost+SMP-Boundary, Local-Sum-Cost+Local-Boundary)替换原本的所有算子Cost相加。

需要对四个设计进行消融实验，对应的optimizer应该位于simple_dp_ablation_optimizer.py中。

## Remote Ray experiments

Future experiments must use remote Ray actors for both profiling and execution.
Run code in the actual Docker container and activate its env/bin/activate first.
Before constructing datasets in a custom experiment script, call
cedar.pipes.ray_variant.configure_remote_ray_experiment().
The default placement resource is cedar_remote; it must not be advertised on
the driver node. Boundary calibration must record actual remote actor locations.
Do not accept an absent, legacy, local or failed Ray boundary calibration and
do not silently fall back to a bandwidth constant. Preserve calibration failure
observations and historical experiment profiles/results separately.

## Shared profile contract for future experiments (2026-09-19)

All optimizer comparisons must use the same dual profile generated by the
default layered protocol: retain original baseline latencies/throughput,
offload whole-pipeline throughput, and legacy TF-fusion measurements, then
append isolated backend_compute, operator_affine, scaling, object-boundary and
transport measurements. Non-DP optimizers consume legacy entries; new simple-DP
and PICO consume new entries. old_dp_boundary remains the legacy-profile control.
Do not compare an optimizer's isolated modeled throughput against another
optimizer's measured legacy throughput as if they were interchangeable.
New layered profiles include real-object SMP aggregate transport curves by
default. Legacy-only profiling remains for explicit historical/debug reproduction;
it must not be used for future optimizer comparison experiments.
The workers-width-boundary CPU width range follows the selected W's separate
Ray/SMP CPU slices; CUDA blocks remain width 1. Results produced before this
fix did not test width allocation, because that variant only searched width 1.
Existing experiment snapshots are immutable and must not be silently patched.

## Unified affine operator cost (2026-09-19)

The per-data/per-record operator classification is removed. Every priced
operator uses the measured `cost(record) = k * input_bytes + b` from
`physical_model.operator_affine`; a cost that is flat in the payload is the
`k = 0` member of the same family, not a separate regime. Profiling must not
abstain from an operator it measured, and an optimizer asked to price an
operator with no fitted coefficients must fail instead of falling back to
byte-proportional compute. Only the explicit historical cost controls
(`old_dp_optimizer`, `old_dp_boundary`, `SimpleDpOptimizer`,
`DpTwoStageOptimizer`, `ExpOptimizer`) may price compute by serialized byte
volume, and they must declare `uses_affine_operator_cost = False`. CLIP/BLIP
metadata-invariance evidence is reported as measured slope/intercept plus its
acceptance gate, not as a per-record label.
